Audit date: 2026-11-14. Baseline: `main`, `c7b88d752ce7594674ee0e6c38bf636732cb6195`, package `0.1.0`. Authority: all 379 lines of [GAMEPLAY.md](GAMEPLAY.md), including sections 11–12. References below use its section, named rule/table, and decision/event identifier; quoted requirements retain the specification wording. `design-references` was excluded. No gameplay changes were made.

**Status discipline:** VERIFIED means the stated scope was exercised successfully, not just found in source. IMPLEMENTED BUT UNVERIFIED means code exists without sufficient execution evidence. PARTIAL means only part of the requirement exists. MISSING means no active implementation was found. INCORRECT means the active behavior contradicts the requirement. BLOCKED means an acceptance result needs missing data or human evidence. A passing legacy test does not establish specification compliance. See [BASELINE_AUDIT.md](BASELINE_AUDIT.md) for execution results and limitations.
